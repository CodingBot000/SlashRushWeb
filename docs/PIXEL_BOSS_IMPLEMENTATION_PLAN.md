# 픽셀 영체 보스 적용 계획

구현 상태: 2026-08-18 적용 및 검증 완료

## 목표

기존 보스 전투 규칙과 체력·판정·HUD는 유지하고, `boss-pixel-v1`의 분리 에셋을 실제 Phaser 보스에 적용한다. 보스는 불꽃 영체 위에 갑옷이 떠 있는 구조로 렌더링하며, 각 입력 패턴이 화면만 보고도 구분되도록 부위별 움직임을 연결한다.

## 적용 범위

- 불꽃 영체 본체와 주변 오라 스프라이트 애니메이션 적용
- 머리, 오른팔·어깨, 왼팔·어깨·검, 허리 갑옷의 독립 레이어 적용
- 기본 호흡, 부유, 갑옷별 위상차 움직임 적용
- `TAP`, `TAP TAP`, `HOLD`, `WAIT` 패턴별 전용 액션 적용
- 피격 떨림, 발광, 격파 분해·소멸 적용
- 데스크톱 1280×720 및 모바일 가로 화면에서 위치·크기 검증

게임 규칙, 입력 판정 시간, 보스 체력, 데미지 수치는 변경하지 않는다. 기존 Godot 보스 이미지와 조각 에셋도 삭제하지 않는다.

## 렌더링 계층과 배치

마스터 좌표계는 `640×725`, 원점은 좌상단이다. 런타임에서는 부모 컨테이너 하나만 화면 좌표와 배율을 담당한다.

| 순서 | 레이어 | 기본 위치 | 회전축 |
| --- | --- | --- | --- |
| 1 | 주변 불꽃 오라 | `(71, 47)` | 정적 배치 |
| 2 | 불꽃 영체 본체 | `(66, 0)` | 정적 배치 |
| 3 | 허리 갑옷 | `(392, 390)` | 이미지 origin `(0.545679, 0.311189)` |
| 4 | 머리 갑옷 | `(286, 285)` | 이미지 origin `(0.595652, 0.905512)` |
| 5 | 오른팔·어깨 | `(377, 220)` | 이미지 origin `(0.192593, 0.383838)` |
| 6 | 왼팔·어깨·검 | `(210, 345)` | 이미지 origin `(0.514986, 0.498008)` |

기본 화면 배치는 우측 전투 영역 안에서 마스터 컨테이너를 약 `0.75`배로 표시한다. 각 부위는 원본 피벗 좌표를 그대로 사용해 작은 회전에서도 이음새가 벌어지지 않게 한다. 모든 픽셀 보스 텍스처는 nearest 필터를 사용한다.

## 기본 동작

- 영체 본체: `0 → 1 → 2 → 1`, 프레임당 220ms 반복
- 주변 불꽃: `0 → 1 → 2 → 3`, 프레임당 120ms 반복, ADD 블렌딩
- 전체: 느린 상하 부유와 미세한 좌우 흔들림
- 머리: 호흡에 맞춘 작은 끄덕임
- 허리: 머리와 반대 위상의 기울기
- 오른팔과 왼팔: 서로 다른 주기의 미세 회전으로 기계적인 동시 움직임을 피함

## 공격 패턴별 액션

### TAP

오른팔을 뒤로 당긴 뒤 앞으로 빠르게 내지르는 단타. 타격 순간 몸통과 머리가 반대 방향으로 반동하고 영체가 짧게 밝아진다.

### TAP TAP

첫 타는 오른팔 내려치기, 두 번째 타는 왼팔의 검 베기다. 준비 단계에서 양팔을 벌리고, 타격 구간을 두 번으로 나눠 실루엣과 리듬이 명확하게 보이도록 한다.

### HOLD

왼팔·어깨·검을 천천히 들어 올리면서 오라와 영체가 충전되고, 타격 구간에 검을 강하게 내려친다. 요청한 "팔을 올렸다가 내려치는" 동작의 주 패턴으로 사용한다.

### WAIT

팔은 공격 자세로 들어가지 않는다. 갑옷 움직임이 잠시 잦아들고 영체와 오라만 크게 맥동한 뒤 원래 상태로 돌아온다. 공격처럼 보이는 빠른 내려치기를 넣지 않아 대기 패턴임을 구분한다.

## 피격과 격파

- 피격: 전체 컨테이너의 짧은 고주파 떨림, 갑옷의 개별 지연 떨림, 영체의 백색·적색 점멸
- 격파: 영체와 오라는 축소·소멸하고 갑옷 네 부위는 서로 다른 방향으로 흩어지며 회전·페이드아웃
- 기존 보스 조각 파티클은 전투 피드백 호환을 위해 유지

## 검증 기준

- TypeScript 빌드와 기존 단위 테스트 통과
- 기존 보스 시작·입력·격파 호출 흐름에 회귀 없음
- 각 패턴의 시작, 타격, 회복 단계가 수치 테스트에서 구분됨
- 실제 브라우저에서 보스 진입 후 불꽃 애니메이션과 네 가지 액션 확인
- 데스크톱과 844×390 모바일 가로 화면에서 보스가 잘리거나 HUD 입력 영역을 가리지 않음

## 구현 결과

- `BootScene`에서 영체·오라 스프라이트 시트와 갑옷 네 레이어를 로드하고 nearest 필터를 적용했다.
- `BossVisualController`를 새 레이어 구조로 교체하고 기본 부유, 네 공격 패턴, 피격, 격파 모션을 적용했다.
- 기존 보스 전투 규칙과 입력 시간은 변경하지 않았다.
- 빌드, 단위 테스트, 데스크톱·모바일 가로 E2E와 실제 브라우저 화면 검증을 통과했다.
